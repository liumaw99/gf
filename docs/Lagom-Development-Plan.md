# Lagom 阶段性详细开发计划

> 包含名人蒸馏系统的完整开发路线图  
> 技术栈：Flutter + Riverpod / Go + Gin + PostgreSQL / 云端 AI  
> 总周期：4 个月（MVP + 名人系统）

---

## 一、里程碑总览

```
Phase 1          Phase 2          Phase 3          Phase 4
Month 1          Month 2          Month 3          Month 4
Week 1-2         Week 3-6         Week 7-10        Week 11-16
├────────────────┼────────────────┼────────────────┼────────────────┤
│ 基础设施       │ 核心功能       │ 名人系统       │ 测试优化       │
│ + 基础伙伴     │ + 习惯引擎     │ + 蒸馏引擎     │ + 上架发布     │
└────────────────┴────────────────┴────────────────┴────────────────┘
        ↓               ↓               ↓               ↓
   MVP 基础版      MVP 完整版      v1.0 名人版      v1.0 正式版
```

## 五、Phase 4: 测试优化 + 上架（Week 13-16）

### 5.1 Week 13-14: 全面测试

| 测试类型 | 内容 | 时间 | 通过标准 |
|----------|------|------|----------|
| 单元测试 | 核心算法（HSI、推荐、亲密度）| 3 天 | 覆盖率 > 70% |
| 集成测试 | API 端到端、前后端联调 | 3 天 | 核心流程 0 bug |
| AI 质量测试 | 12 个角色 × 20 个场景 | 4 天 | 盲测胜率 > 70% |
| 性能测试 | AI 延迟、App 启动、内存 | 2 天 | 延迟 < 5s |
| 用户体验测试 | 10-20 位种子用户内测 | 5 天 | NPS > 40 |

### 5.2 Week 15: 优化修复

根据测试反馈修复问题，重点：
- [ ] AI 回复过长 → 增加长度限制
- [ ] 角色切换卡顿 → 优化本地缓存
- [ ] 某些角色"不像" → 调整 Prompt
- [ ] 用户反馈功能缺失 → 评估是否加入 MVP

### 5.3 Week 16: 上架准备

## 八、风险管理

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
| AI 角色风格不够像 | 中 | 高 | 提前准备 3 轮盲测 + Prompt 迭代 |
| AI API 成本超预期 | 中 | 高 | 缓存策略 + 意图分类减少调用 |
| 开发进度延期 | 高 | 中 | MVP 可缩减：优先 3 个名人角色 |
| 名人版权争议 | 低 | 高 | 使用已故/公开领域人物优先 |
| App Store 审核被拒 | 中 | 中 | 预留 1 周修改时间 |
| 用户留存率低 | 中 | 高 | 早期种子用户深度访谈 |

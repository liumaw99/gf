# Lagom 产品功能设计文档

> 版本：v1.0  
> 目标：定义 Lagom App 的完整功能规格，作为开发实施的单一事实来源  
> 读者：开发者、设计师、测试人员

---

## 一、产品概述

### 1.1 产品定义

Lagom 是一款基于 AI 情感陪伴的自律养成应用。核心体验不是"打卡工具"，而是一个"理解用户、陪伴成长"的 AI 伙伴。用户通过与 AI 伙伴的自然对话，设定目标、接收个性化微习惯建议、记录成长，并在想放弃时获得情感支持。

### 1.2 核心价值主张

| 为谁 | 解决什么问题 | 如何做到 | 与其他方案的区别 |
|------|-------------|----------|-----------------|
| 18-35 岁想自律但难以坚持的人 | 孤独地对抗惰性，反复失败后的自我否定 | AI 伙伴持续陪伴，微习惯降低门槛，失败时共情而非惩罚 | 传统工具冰冷机械，Lagom 温暖理解 |

### 1.3 产品原则

1. **对话优先**：打开 App 第一眼是 AI 伙伴，不是任务列表
2. **少即是多**：每天只推荐"一件小事"，降低选择焦虑
3. **容错设计**：失败不惩罚、不断签、不标红
4. **隐私默认**：敏感数据本地存储，用户拥有完全控制权
5. **正向循环**：每一个小行动都有温暖的即时反馈

## 三、模块 A：AI 伙伴系统

### A1. 伙伴创建与性格定制

#### 功能描述
首次启动时，用户通过一段轻松的对话创建自己的 AI 伙伴。伙伴不是预设的 NPC，而是根据用户的性格、目标、偏好动态生成的独特存在。

#### 详细交互流程

```
【启动页】温暖的品牌动画 → 进入伙伴创建

【步骤1】选择基础形象（视觉锚点）
- 提供 6 个基础形象选项：
  1. 暖橙小狐狸（活泼鼓励型）
  2. 蓝灰小猫咪（温柔安静型）
  3. 翠绿小树懒（沉稳耐心型）
  4. 金黄小狮子（激励挑战型）
  5. 粉紫小兔子（可爱治愈型）
  6. 深棕小熊（可靠陪伴型）
- 用户选择后，伙伴开始"自我介绍"（语音+文字）

【步骤2】5个 onboarding 问题（通过对话自然进行）
Q1: "嗨，我是 [伙伴名]！你平时更喜欢怎么叫我？"
    → 用户自定义称呼（默认基于形象）

Q2: "我想更了解你～你最近最想养成的一个习惯是什么？"
    → 用户自由输入，AI 识别意图和分类

Q3: "如果要用一个词形容你现在的状态，你会选哪个？"
    → 选项：充满干劲 / 有点疲惫 / 焦虑不安 / 迷茫困惑 / 平静稳定
    → 影响伙伴的初始沟通风格

Q4: "你更喜欢什么样的鼓励方式？"
    → 选项：温柔打气 / 直球激励 / 幽默调侃 / 默默陪伴
    → 影响伙伴的"性格档案"

Q5: "如果今天你只想做一件事，你最希望是什么？"
    → 了解用户的真实优先级

【步骤3】伙伴正式"诞生"
- 播放简短的诞生动画
- 伙伴说出第一句话："从今天起，我会一直陪着你。我们一起慢慢来，不急。"
- 进入主界面（聊天界面）
```

#### 数据模型

```dart
class CompanionConfig {
  final String id;
  final String name;              // 用户自定义称呼
  final String avatarType;        // 形象类型 fox/cat/sloth/lion/rabbit/bear
  final String personalityType;   // 性格档案 gentle/energetic/humorous/calm
  final String encouragementStyle; // 鼓励风格 soft/direct/humor/silent
  final String voiceType;         // 语音类型（V2阶段）
  final int growthLevel;          // 成长等级 1-50
  final double relationshipScore; // 亲密度 0.0-1.0
  final List<String> unlockedMemories; // 共同回忆
  final DateTime createdAt;
}
```

### A2. 自然对话交互

#### 功能描述
主界面是一个聊天界面，用户可以像和朋友聊天一样与 AI 伙伴交流。对话不是简单的问答，而是有上下文记忆、情感理解、主动关怀的持续关系。

#### 界面设计

```
┌─────────────────────────────┐
│ ← Lagom           ⚙️        │  // 顶部栏，简洁
├─────────────────────────────┤
│                             │

│             怎么样？        │
│                             │
│                    有点累   │
│                    😮‍💨      │
│                             │
│  [伙伴头像] 辛苦啦～要不要  │
│             今天只做一件    │
│             超小的事？      │
│                             │
│                             │
│  ─────────────────────────  │  // 今日推荐卡片
│  🌟 今天的一件小事          │
│  喝一大杯水                 │
│  [完成] [换个] [晚点]       │
│  ─────────────────────────  │
│                             │
│  [伙伴头像] 对了，昨天你说  │
│             想早睡，昨晚    │
│             几点睡的呀？    │
│                             │
├─────────────────────────────┤
│ 🎙️ │  和伙伴聊聊...  │ 📎 │  // 底部输入栏
└─────────────────────────────┘
```

#### 对话场景覆盖

| 用户意图 | AI 伙伴回应策略 | 示例 |
|----------|----------------|------|
| 报告完成 | 具体表扬 + 关联成长 | "太棒了！这是你连续第5天喝水，你的身体一定在感谢你～" |
| 报告失败 | 共情 + 分析 + 降低门槛 | "没关系，不想运动的时候，换上运动鞋就是胜利。今天就这样？" |
| 表达情绪 | 情绪识别 + 适当回应 | "听起来你今天压力很大。要不要我们先不聊任务，就聊会儿天？" |
| 寻求建议 | 个性化建议 + 选项提供 | "根据你过去的记录，下午3点你状态最好。要不要把最难的任务放那个时间？" |
| 闲聊 | 友好回应 + 适度引导 | "哈哈这个梗我也懂！对了，你今天的'一件小事'想好了吗？" |
| 抱怨/发泄 | 倾听 + 认可 + 不急于解决 | "嗯嗯，我在听。这种感觉确实很难受。" |

#### 技术实现要点
- 使用 SSE (Server-Sent Events) 实现打字机效果的流式回复
- 每次对话附带上下文（最近 10 轮 + 关键记忆摘要）
- 设置回复长度限制（一般不超过 100 字，保持轻松感）
- 预设情感化开场白库（早安/午安/晚安/周末/节日等）

### A3. 情绪状态感知

#### 功能描述
AI 伙伴通过多维度信号推断用户的当前情绪状态，并动态调整沟通策略和任务推荐。

#### 感知信号

| 信号类型 | 数据来源 | 推断逻辑 |
|----------|----------|----------|
| 完成率变化 | 最近 7 天打卡数据 | 完成率骤降 → 可能疲惫或遇到困难 |
| 活跃时段偏移 | 用户打开 App 的时间 | 连续几天深夜打开 → 可能作息紊乱 |
| 对话情绪词 | 用户消息中的情感词汇 | "累""烦""不想" → 负面情绪 |
| 消息响应延迟 | 用户回复 AI 的时间 | 延迟增加 → 可能忙碌或回避 |
| 主动发起频率 | 用户主动发消息 vs 被动回复 | 被动为主 → 可能动力不足 |
| 手动情绪标记 | 用户主动标记心情（可选） | 直接输入，权重最高 |

#### 情绪状态与策略映射

```dart
enum UserMood {
  energetic,    // 情绪高涨 → 适度挑战，推荐稍难的任务
  calm,         // 平静稳定 → 标准推荐
  tired,        // 疲惫 → 降低要求，增加陪伴
  stressed,     // 焦虑 → 减少任务，引导放松
  frustrated,   // 挫败 → 积极共情，帮助复盘
  withdrawn,    // 回避 → 温柔等待，不施加压力
}
```

#### 示例场景

```
用户状态：连续3天完成率从 80% 降到 20%，昨晚凌晨2点打开 App

伙伴判断：tired + stressed

伙伴行动：
1. 不推送任何新任务
2. 发送消息："最近是不是特别忙？我注意到你这几天都没怎么休息好。"
3. 如果用户回应，引导表达；如果不回应，次日再 gently 关心
4. 次日推荐任务降级为"今天早点睡"或"喝一杯温水"
```

### A4. 智能计划生成与动态调整

#### 功能描述
用户说出目标，AI 生成科学的渐进计划。计划不是固定的，而是根据每天的执行情况动态调整。

#### 计划生成流程

```
用户输入："我想养成每天运动的习惯"

AI 处理：
1. 目标解析：运动 → 大类"运动健身"
2. 用户画像匹配：根据用户历史判断偏好（室内/户外、轻度/中度）
3. 渐进计划生成（21天周期）：

   Week 1: 启动期（降低阻力）
   - Day 1-3: 穿上运动鞋，出门走3分钟
   - Day 4-5: 出门走5分钟
   - Day 6-7: 出门走8分钟

   Week 2: 建立期（逐步增加）
   - Day 8-10: 快走10分钟
   - Day 11-12: 快走15分钟
   - Day 13-14: 快走20分钟或慢跑5分钟

   Week 3: 巩固期（稳定节奏）
   - Day 15-21: 每天运动20-30分钟（用户自选类型）

4. 存储为 Habit 对象，关联 MicroAction 列表
```

#### 动态调整规则

| 触发条件 | 调整策略 |
|----------|----------|
| 连续 3 天完成 | 微幅提升难度（+10%） |
| 连续 2 天未完成 | 主动询问原因，提供降低难度选项 |
| 用户反馈"太简单了" | 跳过当前阶段，进入下一阶段 |
| 用户反馈"太难了" | 回退到上一阶段，或拆解为更小的动作 |
| 生病/出差等特殊事件 | 一键暂停计划，设置恢复提醒 |

## 四、模块 B：微习惯引擎

### B1. 每日一件小事（Daily One Thing）

#### 功能描述
每天 AI 伙伴只向用户推荐"一件"最重要的小事。这件小事基于用户目标、当前进度、情绪状态和当日时间综合计算。

#### 推荐算法逻辑

```dart
class DailyOneThingRecommender {
  String recommend(User user) {
    // 1. 获取用户所有活跃 habit
    final habits = user.activeHabits;
    
    // 2. 计算每个 habit 的优先级分数
    final scoredHabits = habits.map((h) {
      double score = 0;
      
      // 紧急度：连续未完成天数越多，分数越高
      score += h.missedDays * 10;
      
      // 重要性：用户标记的优先级
      score += h.priority * 5;
      
      // 时间匹配度：当前时间是否在 habit 的最佳时段
      score += h.bestTimeMatch(now) * 3;
      
      // 情绪适配度：当前情绪是否适合该 habit
      score += h.moodMatch(user.currentMood) * 2;
      
      return ScoredHabit(h, score);
    });
    
    // 3. 返回分数最高的 habit 的当前阶段微行动
    final topHabit = scoredHabits.maxBy((s) => s.score);
    return topHabit.habit.currentMicroAction;
  }
}
```

#### 用户交互

```
伙伴消息："今天的一件小事准备好了～"

[卡片弹出]
┌──────────────────────────────┐
│  🌟 今天的一件小事            │
│                              │
│  喝一大杯水（500ml）          │
│                              │
│  [ 轻松完成 ✓ ]              │
│                              │
│  [ 换一个 🤔 ]  [ 晚点再说 ⏰ ] │
└──────────────────────────────┘

用户点击"轻松完成"：
→ 播放完成动画 + 伙伴语音"太棒了！"
→ 记录到 DailyLog
→ 伙伴亲密度微增
→ 不立即推送下一个任务（保持"少即是多"）
```

### B2. 习惯养成可视化

#### 功能描述
用温暖、非焦虑的方式可视化习惯养成进度。核心指标不是"连续天数"，而是"习惯强度指数"。

#### 习惯强度指数（Habit Strength Index）

```
HSI = (完成频率 × 0.4) + (完成质量 × 0.3) + (情绪一致性 × 0.3)

- 完成频率：最近 30 天完成率（允许缓冲日）
- 完成质量：用户自评 + AI 评估（是否敷衍）
- 情绪一致性：完成时是否心情愉悦（被迫完成权重降低）

HSI 范围：0-100
0-30: 萌芽期 🌱
30-60: 成长期 🌿
60-85: 稳定期 🌳
85-100: 内化期 ✨
```

#### 可视化设计

不采用传统的日历格子，而是：

```
【伙伴家园页面】

    🏠 伙伴的小屋
    
    周围的环境随着习惯养成进度变化：
    
    HSI 0-30: 荒地，只有一棵小苗
    HSI 30-60: 开始出现草地和小花
    HSI 60-85: 花园，有蝴蝶和小动物
    HSI 85-100: 繁茂森林，有瀑布和彩虹
    
    每个 habit 对应家园中的一个元素：
    - 运动 habit → 一棵成长中的树
    - 喝水 habit → 一条小溪
    - 阅读 habit → 一个书架
    - 早睡 habit → 星空和月亮
```

#### 缓冲日设计

```
每周自动获得 2 个"缓冲日"（Buffer Day）
- 缓冲日不完成任何 habit 不扣分
- 连续使用缓冲日超过 3 天，伙伴会 gentle 关心
- 缓冲日不可累积，每周一重置
- 视觉提示：缓冲日用柔和的紫色标记，而非红色的"失败"
```

### B3. 场景化触发器

#### 功能描述
在合适的时间、合适的地点，以合适的方式推送提醒。不是固定时间的轰炸，而是智能触发。

#### 触发器类型

| 触发器 | 触发条件 | 示例 |
|--------|----------|------|
| 时间触发 | 用户历史最佳时段 | "你下午3点通常状态很好，要不要现在做这件事？" |
| 地点触发 | 地理围栏（V2） | 检测到用户在健身房附近 → "到健身房了，今天运动吗？" |
| 行为触发 | 设备使用模式 | 检测到刷手机超过 45 分钟 → "眼睛累了，休息一下吧？" |
| 事件触发 | 日历事件 | 会议结束后 5 分钟 → "会议结束了，喝杯水吧？" |
| 情绪触发 | AI 判断 | 检测到用户情绪低落 → 不推送任务，只发送关心 |
| 社交触发 | 好友互动（V2） | 好友完成了 habit → "小明刚刚完成了他的目标，你呢？" |

#### 通知设计原则

```
❌ 差的通知："该喝水了"
✅ 好的通知："嘿，我刚刚想起你，现在在忙吗？不忙的话喝口水吧～"

❌ 差的通知："今日任务未完成"
✅ 好的通知：（不发送，等用户主动打开 App 后伙伴再说）
```

### B4. 失败复盘与重新启动

#### 功能描述
当用户连续失败时，AI 伙伴主动发起温和的复盘对话，帮助用户找到原因、调整计划、重新出发。

#### 复盘流程

```
触发条件：某个 habit 连续 3 天未标记完成

伙伴消息：
"我注意到'运动'这个目标最近几天没有进度，我想了解一下是不是遇到什么困难了？"
"不用担心，这里没有对错，只是想帮你找到更适合的方式。"

选项卡片：
┌──────────────────────────────┐
│ 你觉得主要是哪个原因呢？      │
│                              │
│  [ 目标太大了 😰 ]           │
│  [ 时间总是不合适 ⏰ ]        │
│  [ 最近太累了 😮‍💨 ]          │
│  [ 单纯忘记了 🤦 ]            │
│  [ 不想聊这个 🚫 ]            │
└──────────────────────────────┘

根据选择：
- 目标太大 → 降级到上一阶段的微行动
- 时间不合适 → 重新分析用户的最佳时段
- 太累了 → 暂停计划 3 天，只保留最简单的行动
- 忘记了 → 优化提醒时间和方式
- 不想聊 → 尊重用户，3 天后再次 gentle 询问
```

#### 关键原则

- **绝不展示"连续失败 X 天"**
- **绝不使用红色、警告图标**
- **失败不影响伙伴成长**（伙伴的成长绑定"尝试"而非"成功"）
- **用户永远有选择权**：可以降低难度、暂停、或换目标

## 五、模块 C：专注空间

### C1. 沉浸式专注模式

#### 功能描述
用户进入专注时，AI 伙伴以"陪伴者"身份在场，提供场景化的专注环境。

#### 专注启动流程

```
用户："我要专注工作了"

伙伴："好呀，我陪你！想选个场景吗？"

[场景选择]
┌─────────────────────────────────────┐
```

### C2. 防分心智能锁机

#### 功能描述
专注期间提供不同级别的防分心保护。

#### 模式设计

```dart
enum FocusMode {
  gentle,   // 温和模式：离开App时伙伴发送提醒，不强制
  normal,   // 标准模式：离开App需确认"确定要放弃吗？"
  strict,   // 严格模式：限制其他App使用（通过系统权限）
}
```

#### 智能锁机

```
功能：AI 学习用户的"分心 App 清单"

学习期（前 2 周）：
- 记录用户专注期间最常切换去的 App
- 自动生成分心 App 排行榜

执行期：
- 温和模式：打开分心 App 时，系统通知"你在专注中哦，确定要去吗？"
- 严格模式：需要用户手动将 App 加入白名单才能使用
```

### C3. 专注数据洞察

#### 功能描述
不仅统计"专注时长"，更分析"专注质量"和"高效时段"。

#### 数据维度

| 维度 | 说明 | 用途 |
|------|------|------|
| 总专注时长 | 累计时间 | 成长报告展示 |
| 平均专注时长 | 每次专注的平均长度 | 识别注意力持续时间 |
| 中断次数 | 离开 App 的次数 | 评估专注质量 |
| 高效时段 | 完成质量最高的时间段 | 优化任务推荐时间 |
| 场景偏好 | 哪种场景下专注质量最高 | 个性化推荐默认场景 |
| 习惯关联 | 专注前后完成了什么 habit | 发现习惯间的协同效应 |

## 六、模块 D：成长档案

### D1. AI 驱动的每日反思

#### 功能描述
每天结束时（或用户主动触发），AI 伙伴引导用户进行 2-3 分钟的语音反思。

#### 反思流程

```
时间：晚上 9 点（可自定义）

伙伴推送："今天快结束了，要不要一起回顾一下？"

[进入反思模式 - 全屏，柔和背景]

Q1（语音回答）："今天有没有哪件小事让你感到开心？"
→ AI 转文字，提取关键词

Q2（语音回答）："如果给今天的自己一句话，你会说什么？"
→ 记录为"今日金句"

Q3（选择题）："整体来说，今天的感觉是？"
→ 😊 不错 / 🙂 还行 / 😐 一般 / 😔 不太好

生成"今日成长摘要"：
┌──────────────────────────────┐
│  📅 5月29日 成长摘要          │
│                              │
│  ✅ 完成：喝水、阅读10分钟     │
│  💬 今日金句："慢慢来，比较快" │
│  😊 心情：不错                │
│  🌟 亮点：早上主动开始专注    │
│                              │
│  [保存到成长时间线]           │
└──────────────────────────────┘
```
